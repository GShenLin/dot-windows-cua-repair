# 本机验证与收尾

本 Skill 按本次相同故障场景执行已验证的四层修复。**不需要 Dot 确认，不向用户转交测试任务，不等待另一端的反馈。** 历史成功依据见 session-2026-10-10.md；每次新使用仍如实记录本机执行结果。

## 必做本机检查

1. 确认安装器识别的是受支持构建，四层修复均已选择；已有完整历史修复则核对原维修清单，不重复覆盖。
2. 核对全部安装文件与备份哈希，确认回滚清单完整；仅 platform 对 untrusted allowlist 增加两项平台变量，其他权限和策略保持原样。
3. 核对自己的 Codex 父进程及允许环境字段。只比较存在性和一致性，不输出连接身份或代理凭证。
4. 用配套脚本执行 Node 语法与 MXC 启动验证，确认不再发生平台目录或启动目录错误。合成启动测试只证明启动，不冒充真实网页自测。
5. 恢复临时计时插桩，清理本轮诊断进程与测试页，汇报一次完整结果。不会因缺少 Dot 回传而留下“等待确认”的任务。

## 激活说明

环境修复对新启动的 MCP 进程生效；`js_reset` 只重置 kernel，不能刷新其父环境。按当前环境可用方式重新加载自己的工具进程；不要强杀主程序或无关会话。若当前旧进程仍保留旧环境，说明“修复已安装，新工具进程生效”，不要求用户创建 Dot 任务来确认。

## 可选本机网页自测

当前任务具备 CUA 且能加载修复时，按实际工具文档一次完成下列测试。首次调用遵守工具初始化要求，每项正常时限执行一次，失败不循环重试：

1. 查询状态，确认 iab。
2. 创建隐藏页打开 `https://example.com`，确认返回对象及隐藏状态。
3. 读取实际可见正文，枚举页 ID、标题和 URL。
4. 下一次调用复用该对象，根据已读页面点击 Learn more，确认跳转。
5. 返回并读取状态，获取网页截图。
6. 关闭自建页并枚举确认，保留用户原有页面。

创建超时后页面可能已存在；仅对明确归属本轮的 ID 做一次绑定/清理尝试，无法确认归属就不关闭。记录原始错误、北京时间和清理结果。可选自测不能执行时只说明原因，不另行要求 Dot 配合。

## 完成报告

分别列出四项安装结果、本机检查、激活状态、可选网页自测和回滚位置。网页自测未运行就写“未运行”，不写“已通过”，也不写“待 Dot 确认”。对话恢复链和原生屏幕/鼠标权限是独立事项，不随四层浏览器修复一并宣称解决。
